🔬 IA LOTO V61 — Froids 300

Laboratoire statistique, pas prédicteur. Les numéros froids n’ont pas plus de chances de sortir. Les enregistrements locaux ne prouvent pas l’antériorité. Aucune version n’est garantie sans erreur.

1. Source des tirages

Charger le CSV FDJ fourni avec l’application ou importer un CSV extrait d’une archive FDJ. Les ZIP ne sont pas lus directement.

Aucune source chargée.

2. Calcul strict

Charger une source d’abord.

Un .tsq n’est pas un reçu signé. Le fichier .tsr doit être vérifié avec une autorité de confiance externe. Une réponse .tsr vérifiée est indispensable.

3. Audit et performances historiques

Vérification de la cohérence du CSV et backtest sans utilisation du tirage à prédire. Les résultats historiques ne garantissent pas les résultats futurs.

4. Compétition de modèles — validation chronologique
Compare cinq méthodes sur les mêmes tirages. Les 100 derniers tirages valides constituent une période de validation non utilisée pour sélectionner le modèle : les méthodes et leurs paramètres sont fixés dans le code avant le test. Aucune supériorité n'est présumée.
5. Moteur adaptatif — véritable test hors calibration
Le choix de modèle est recalculé avant chaque tirage, uniquement sur 120 tirages antérieurs. Chaque modèle utilise les 300 tirages précédents. Une pénalité fixe limite la sélection opportuniste. Le dernier bloc de 100 tirages est réservé à l’évaluation externe.
6. Tests automatiques du moteur
Exécuter des tests de non-régression directement sur cet appareil. Ils ne remplacent pas les essais de Safari ni un audit externe.
7. Contrôle du rapport exporté
Charge un rapport JSON pour recalculer son empreinte. Pour une preuve d'antériorité, conserve aussi le reçu .tsr et fais vérifier sa signature avec une autorité de confiance.
8. Vérification JSON ↔ TSQ
Sélectionne le JSON exporté et sa demande .tsq. Le logiciel compare leurs empreintes octet par octet. Ce contrôle ne valide pas une réponse .tsr ni son certificat.
9. Journal local
Le journal local est modifiable ou effaçable : pour prouver une prévision avant le tirage, horodater le rapport chez un tiers indépendant et conserver son reçu vérifiable.
Limites et garanties
Le calcul utilise exactement les 300 tirages datés avant la cible, avec égalités départagées par numéro croissant. Un SHA-256 confirme l’identité des octets, pas leur authenticité FDJ. Les contrôles d’écart de dates ne prouvent pas que tous les tirages officiels sont présents. L’actualisation depuis une URL HTTPS est facultative et dépend du serveur FDJ et de CORS ; aucune garantie de disponibilité. La demande RFC 3161 .tsq est générée dans le navigateur, mais la réponse .tsr doit être obtenue auprès d’un tiers et vérifiée avec une chaîne de confiance externe. La V59 ne certifie pas elle-même les reçus.
